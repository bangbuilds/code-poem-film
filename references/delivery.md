# 出片与交付

```bash
python3 tools/film.py render                    # 检查 → 渲染 → 核对 → 打包，约 1 分钟
python3 tools/film.py render --out <名字>        # 另存一个文件名（比如换了音色的对比版）
python3 tools/film.py render --package-only     # 已有母版时只重新核对和打包
```

## 产出的文件

| 文件 | 用途 |
|---|---|
| `renders/<slug>.mp4` | 母版，约 2 MB/秒。留着 |
| `renders/<slug>-upload.mp4` | 上传版。短片自动压到 9.5 MB 以内（浏览器自动上传的通道一般限 10 MB）；长片压不进去，保留高画质 1080p（一分多钟约 30 MB），请用户自己拖进发布页。**发平台用这个** |
| `renders/<slug>-small.mp4` | 只有长片才有：720p、10 MB 以内，给浏览器自动上传用，画质差一截 |
| `renders/cover.png` | 封面，等于成片第一帧，无损。需要单独传封面的平台用它 |
| `renders/contact.jpg` | 成片里每秒一帧的总览图。交付前最后看一眼 |
| `build/package.json` | 时长、帧数、响度、文件大小、代码行数、渲染秒数、配音调用次数——帖子里的数字从这里取 |

母版和上传版的静态纸纹会让码率偏高，属于正常。

## 平台

| 平台 | 画幅 | 备注 |
|---|---|---|
| X | 16:9 | 缩略图取第一帧，所以封面必须是第一帧（引擎已经这样做） |
| 抖音 / TikTok / 视频号 / 小红书 | 竖版为主 | 这个 skill 目前只出横版。横版能发，但占屏小；要竖版得重排版式，开工前和用户说清楚 |

## 交给用户时说什么

1. 把上传版和封面发给用户看（能发文件就发文件，不要只给路径）。
2. 一段话或一张小表说清：片长、每一段是什么画面、朗诵怎么对的位。
3. **没验证的要明说**：声音你没听过（配乐好不好听、朗诵有没有感情、读音是否自然）；动作的手感你只看过静帧。
4. **和开工前说的不一样的地方**：时长、落款文字、临时做的决定。
5. 用了什么不是自己做的东西：汉字笔画来自开源数据集（hanzi-writer-data，Arphic 公共许可）；朗诵来自语音合成。
6. 音色拿不准时给两版，让用户选；选定后把另一版的文件名告诉用户，是否删除由用户定。

## 实测帖草稿

如果用户要发帖（或者一贯会发），把草稿写进工程里的 `post.md`，不代发。

### 数字从哪来

| 数字 | 出处 |
|---|---|
| 片长、帧数、代码行数、渲染秒数 | `build/package.json` |
| 用户一共说了几句话、每句之后做了多久 | `python3 tools/film.py stats`（读本机的会话记录；只统计「用户说完一句到下一句之前」的工作时间，用户不在的空档不算） |
| 输出了多少 token | 同上。它数不到用户在选择卡片上点的选项，那个要自己数 |
| 节点时刻（分镜确认、第一版出片……） | `logs/PRODUCTION_LOG.md`（过程中用 `film.py log` 记） |

`stats` 读的是 Claude Code 的会话记录。同一个会话里还做过别的事，就用 `--since <时刻>` 截掉前面的。别的工具没有这种记录，就用生产日志里的时刻。把每个数字和它的出处一起写进 `post.md`，以后有人问能答上来。

### 写法

- **有几句写几句**。「一句话出片」只有在真的只说了一句、没有确认和返工时才能说。说了三句、点了五次选项，就写「三句话、点了五下」。这是这类帖子唯一经不起翻的地方。
- **「没用什么」要写准**。可以说：没开 AE、没请画师作曲配音、没用一张图片素材、每一帧都是代码画的。不能说「没用任何素材」（笔画数据是别人的）、「配音也是代码算的」（是语音合成服务）。
- **耗时和 token 要有**：`耗时 85 分钟，输出 30 万 token`。耗时是工作时间；token 报输出 token（上下文反复读取的缓存量大一两个数量级，放在出处里备查）。
- **要有一个让人想争论的点，用问句**：「这算不算干掉了一个动画工作室？」写成结论就是吹牛，写成问句是邀请人来吵。
- **结尾留一个人人能接的问题**（「下一首画哪首诗？」），不要以总结收尾。上面那个争论点本身就可以是结尾。
- **短**。X 的上限是 280（一个汉字算 2），写到 200 左右最好。
- 术语放评论区（canvas、numpy、频谱图），正文说人话（「画面是代码一帧帧画的」）。
- 翻车的细节（哪里悬空了、鼓把旋律盖住了、多音字怎么防的）是很好的评论区素材，比正文里夸自己可信。
- 不主动点名用的是哪家语音服务；要不要 @ 谁、几点发，由用户定。

### 一个可以照着改的结构

```
三句话、点了五下，AI 做出一部带朗诵的动画短片。

没开 AE，没请画师、作曲、配音，没用一张素材图。
李白《早发白帝城》，25 秒，每一帧都是代码画的。

耗时 85 分钟，输出 30 万 token。

这算不算干掉了一个动画工作室？
```
